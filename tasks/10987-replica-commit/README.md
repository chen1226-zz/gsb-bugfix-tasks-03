# 10987 · 复制日志提交索引（replica）

`replica.py` 在单进程内模拟三节点（可选更多）Raft 复制日志，网络丢包/延迟、
节点重启（换主）均可通过 `drop_rate` 与 `elect_leader()` 注入。

接口：`Replica(nodes, rng, drop_rate)` 的 `.append(command)` / `.elect_leader()` /
`.ack_count(command)` / `.committed()`。

| 文件 | 说明 |
| --- | --- |
| `replica.py` | 实现：多数派提交 + 日志匹配 + 任期投票限制 |
| `chaos.py` | 复现脚本：200 组随机丢包 + 随机换主（只读，勿改） |
| `tests/test_replica.py` | unittest 用例 |

## 原 bug

1. `append` 无视确认数，本地追加后立刻 `committed=True` —— 没有多数派就提交；
2. 日志条目不带任期，复制直接整段覆盖，没有日志匹配检查；
3. `elect_leader` 随机选主，且把比新主“更长”的日志截断 —— 落后节点当选
   即可抹掉已提交数据，随后覆盖其他节点，造成历史回退。

## 提交规则（Raft 安全性）

- **多数派**：`append` 返回 `committed=True` 当且仅当该条目复制到 `N//2+1`
  个节点（含主）。未达多数派时 `commit_index` 不动。
- **只提交当前任期**：新条目都带主的当前任期；只有当前任期条目拿到多数派
  确认时才把 `commit_index` 推进到该索引，其前面的旧任期条目被**间接提交**。
- **任期比较（投票限制）**：候选人只有在
  `(末条任期, 末条索引) >= 投票人` 时才能拿到票，因此当选者日志包含全部
  多数派已提交条目，换主不可能丢失已提交数据。
- **日志匹配（AppendEntries）**：同步时按任期找最长公共前缀，仅删除与主
  冲突的**未提交**后缀，再补齐缺失条目；已提交条目因任期/索引唯一从不冲突。
- **提交水位**：追随者把 `commit_index` 推进到 `min(主水位, 自身末索引)`；
  当选者从投票者吸收已确认水位，避免“日志已含但水位仍旧”的可见性回退。
- 被分区的落后节点不影响可用性；网络恢复后下一次复制/心跳会将其追平
  （`chaos.py` 最后按多数派校验，`tests` 另校验恢复后三节点完全一致）。

## 节点状态机

```
            启动 / 初始
                |
                v
        +---------------+   选举超时(term+1)    +---------------+
        |   Follower    | ------------------->  |  Candidate    |
        |  (被动复制、   |                       |  (拉票：比较    |
        |   推进水位)    | <-------------------  |   末条任期/索引)|
        +---------------+   发现更高任期/当选失败 +---------------+
                ^                                      | |
        心跳/日志|                              多数派票 | | 多数派票不足
        到达即续期|                                      v v
                |                                +---------------+
                +------------------------------- |    Leader     |
                                                 | (追加当前任期， |
                                                 |  多数派才提交)  |
                                                 +-------+-------+
                                                         | 发现更高任期
                                                         v
                                                    Follower
```

单条日志的生命周期：`uncommitted（主本地/少数派，可能被新主截断）`
→ `replicated（多数派持有）` → `committed（当前任期多数派确认，
commit_index 推进，不可回退）` → `applied（committed() 可见前缀）`。

## 运行

```
python3 chaos.py                                  # 期望: OK: 200 runs, 0 rollbacks
python3 -m unittest discover -s tests             # 期望: OK（9 个用例）
```

测试覆盖：无丢包复制/前缀/任期推进等既有断言；多数派才提交、脑裂恢复、
落后节点追赶（日志匹配对齐）、任期交叉时未提交尾截断、提交后立即崩溃再恢复。
